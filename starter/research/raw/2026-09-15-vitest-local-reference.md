The speaker cloned Vitest locally under `opensource/vitest` and made it available to the migration agent as a reference. The agent could consult the documentation, implementation and Vitest's own tests, see how Vitest tests its APIs, and use the appropriate APIs in the migration.

This is the user's account of the migration workflow, not a new checkout inspection or a measured claim of perfect API correctness. “Could consult” does not mean the agent read every file. No exact historical revision was supplied.
